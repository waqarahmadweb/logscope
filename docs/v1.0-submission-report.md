### 🔴 Fix before shipping

- [x] **1.1 — Live mode stops polling when the list is empty.** 🔴 High (bug) · S — **Fixed:** `useTailPolling` hoisted into `LogViewer`; `ListScrollPane` receives the shared ref and nulls it on unmount.
  `useTailPolling` runs only inside `ListScrollPane`, which does not mount when
  `items.length === 0`. After Clear log, on an empty log, or when a mute/filter empties the
  visible list, the Live button stays lit but no poll loop exists — new entries never appear;
  muting the last visible rows mid-tail silently kills the tail.
  File: `assets/src/components/LogViewer/index.jsx:748` (mount site) / hook at `:868`.
  **Fix:** hoist `useTailPolling(scrollElementRef)` up into the `LogViewer` component (the hook
  already tolerates a null scroll element via `atTop = true`).

- [x] **1.2 🔒 — POST /settings only requires the grantable `logscope_manage` cap.** 🔴 Med (security) · S
  DELETE /logs was raised to `manage_options`, but a sub-admin holding only the plugin cap can
  still (a) repoint `log_path` at any other `*.log` under ABSPATH/WP_CONTENT — other plugins'
  logs, often full of PII — then read/download it via /logs, and (b) set `alert_webhook_url` to
  an attacker host so the site exfiltrates error data (GET /settings also returns the stored
  webhook URL, itself a bearer secret for Slack-style hooks).
  File: `src/REST/SettingsController.php:78-84`, `:128-196`.
  **Fix:** require `manage_options` for POST /settings (or at minimum for `log_path`,
  `alert_webhook_url`, `alert_email_to`).

- [x] **1.3 — Cron scanner has no read budget.** 🔴 Med (bug) · S
  `scan()` does `read_chunk( $last, $size - $last )` with no clamp. The first tick after
  enabling monitoring (cursor 0) and every post-rotation tick fread the entire log in one
  string → OOM/timeout risk on a multi-hundred-MB log, and first-enable alerts fire on all
  historical fatals at once.
  File: `src/Cron/LogScanner.php:114-115`.
  **Fix:** clamp to `LogRepository::MAX_BYTES_PER_QUERY` (`$last = max( $last, $size - BUDGET )`),
  or seed the cursor to EOF when the toggle flips on.

- [x] **1.4 — Tail appends never update `logs.total`.** 🔴 Med (bug) · S
  `TAIL_APPEND_ENTRIES` grows `items` but not `total`; `hasMoreLogs` compares
  `items.length < total`, so tail-prepended rows can flip it false while unloaded pages remain
  → premature "End of log", dead infinite scroll after stopping Live, stale header count.
  File: `assets/src/store/index.js:874-888` (reducer) / `:1359` (`hasMoreLogs`).
  **Fix:** increment `total` by `incoming.length` on a non-rotated append.

### 🟠 Plugin Check friction (fix before running the check)

- [x] **1.5 — 6 `EscapeOutput.ExceptionNotEscaped` ERRORS in `LogQuery.php`.** 🟠 · S
  The intent was to silence these (JSON-only exception messages) but the annotations are
  misplaced: the `phpcs:ignore` near line 244 sits on the closing `);` line and silences
  nothing; the throws at 148, 165, 280 have no annotation. The 152–161 block shows the correct
  `phpcs:disable/enable` pattern.
  **Fix:** apply that pattern to the other four throw sites. File: `src/Log/LogQuery.php`.

- [x] **1.6 — `IniSet.Risky` warnings on the PCRE budget set/restore.** 🟠 · S
  Value is saved and restored, defensible, but Plugin Check will flag it.
  Files: `src/Log/LogRepository.php:290`, `:328`.
  **Fix:** add a justified `// phpcs:ignore WordPress.PHP.IniSet.Risky` on both lines.

- [x] **1.7 — `require_once vendor/autoload.php` has no `file_exists` guard.** 🟠 · S
  Fine in the shipped zip (`bin/build-zip.ps1` layers in a `--no-dev` vendor), but a reviewer
  testing from a raw GitHub clone fatals.
  File: `logscope.php:27`.
  **Fix:** guard the require and show a graceful admin notice on absence.

- [x] **1.8 — Minor `composer lint` residue.** 🟠 · S — **Fixed:** `@throws` added to `apply_filters`, empty-catch given a no-op body, LogsController alignment resolved, and the settings-test silence-sniff disabled at the file header. Full `phpcs` now exits 0 across all 93 files.

### 🟡 Optional / v1.0.1

- [x] **1.9 — Preset `severity` filter is not length/vocabulary-capped.** 🟡 Med/Low (security) · S
  `sanitise_filters()` accepts any non-empty string into the severity list; the 200-char cap
  only covers the scalar branch → a crafted body can bloat usermeta.
  File: `src/Settings/PresetStore.php:231-242`.
  **Fix:** intersect the severity array with `Severity::all()`.

- [x] **1.10 — Cleared/rotated archives are web-accessible with predictable names.** 🟡 Med (security) · S — **Fixed:** both clear and rotate append a `wp_generate_password(6)` token to the archive name, so names are unguessable/non-enumerable (the prune glob + mtime sort are unaffected).
  `debug.log.cleared-<ts>` / `debug.log.archived-<ts>` are renamed in place inside `wp-content`,
  served as plain text by default server configs, with second-granularity guessable names, and
  persist after the live log is cleared. No `.htaccess`/`index.php` protection exists.
  Files: `src/REST/LogsController.php:289-316`, `src/Log/LogRotator.php:115-141`.
  **Fix:** add a random suffix (`wp_generate_password(8, false)`) to archive names, and/or write
  a deny-all `.htaccess` + `index.php` into the log directory on first rotation/clear.

- [x] **1.11 — Boundary-byte rotation probe false-positives on a non-`\n`-terminated log.** 🟡 Low-Med (bug) · S
  `query()` reports `last_byte = size` even when the file ends mid-line; the next growth tick's
  probe at `since-1` finds a non-newline and declares rotation → spurious full-list replace +
  scroll-to-top + newCount wipe for a mere mid-write race.
  File: `src/Log/LogRepository.php:90-96`.
  **Fix:** clamp the reported `last_byte` back to the offset just past the final `\n` of the
  parsed chunk.

- [x] **1.12 — Page-number pagination overlaps after tail prepends.** 🟡 Low (bug) · S — **Fixed:** LogViewer refetches page 1 on the Live true→false transition, so the shifted newest-first pages don't re-serve on-screen rows.
  After a Live session prepends N rows, `fetchNextLogsPage` requests `page+1` of the shifted
  newest-first list, re-serving on-screen rows as duplicate content (fresh `_clientId`s, so no
  key collision — just dup rows).
  File: `assets/src/components/LogViewer/index.jsx:839-866`.
  **Fix:** refetch page 1 on tail stop, or move to offset/cursor pagination.

- [x] **1.13 — `clearAllLogs` refetch resets the admin's page size.** 🟡 Low (bug) · S
  The refetch passes only `{ page: 1 }` — no `per_page`/filters/`grouped` — so `LOGS_RECEIVED`
  overwrites `logs.perPage` with the server default 50 until reload.
  File: `assets/src/store/index.js:695`.
  **Fix:** build the refetch with the current filters/viewMode/perPage (like `onMuteSelected`).

- [ ] **1.14 — REST nonce in the download URL query string.** 🟡 Low (security) · S
  `downloadLogsUrl()` appends `_wpnonce=` to a browser-navigated URL, so the nonce lands in
  access logs / history. **Deliberately kept for v1.0** — a Blob approach would buffer a
  potentially-50 MB file in JS memory, defeating the streaming design. Revisit if wp.org flags it.
  File: `assets/src/api/client.js:150-157`.

## §3 — Manual test plan

Prereq: **rebuild the JS bundle first** (Phase B) — otherwise items 1–19 test old code. Each
item is *do → expect*.

1. Fresh activate with `WP_DEBUG_LOG` **off** → onboarding warning with the exact wp-config
   snippet; no console errors; dismiss → stays gone this session, reappears in a new session.
   Page has exactly one `<h1>`.
2. Enable `WP_DEBUG` + `WP_DEBUG_LOG`, trigger a notice, warning, and fatal → entries appear with
   correct severity pills, timestamps, file:line.
3. Toggle severity pills (Fatal + Warning) → list narrows, summary chips appear, URL `?severity=`
   updates; click a chip's × → that filter pops off and refetches.
4. Valid regex `wpdb::.*query` → filters + highlights matches; invalid regex `([` → graceful
   empty state, no crash; paste a 250-char pattern → input caps at 200, server accepts.
5. From/To dates spanning one day of known entries → only in-range shown, boundary-day included;
   clear via chip.
6. Source dropdown lists sources from loaded entries; pick one → filters; row ⋮ → "Filter to this
   source" applies the same.
7. 200+ entries: scroll hard and fast to the bottom repeatedly → pages append with no duplicated
   or skipped rows, no double-fetch, footer flips "Showing X of Y" → "End of log · N loaded".
8. Save filters as a preset, clear all, load it → severity/date/source **and search-box text and
   view mode** all restore; delete → confirm prompt, then gone.
9. Switch to **Plain permalinks** → Download button still streams the raw debug.log as an
   attachment (URL joins with `&` after `?rest_route`), content matches disk; switch back.
10. Clear log → confirm modal shows file size → confirm → `.cleared-<ts>` archive on disk, list
    empties, toast names the archive; immediately Clear again → graceful "no log file to clear".
11. Write a line starting with `=1+1` (and ones with commas, quotes, newlines, non-ASCII) → select
    → Export → open CSV in Excel/LibreOffice → formula cell shows literal `'`-prefixed text (does
    NOT evaluate), quoting intact, non-ASCII readable.
12. Unique errors → duplicates collapse with ×count; header select-all + indeterminate state; bulk
    Mute (reason prompt) → groups vanish and appear under Settings → Muted; unmute one → returns.
13. Grouped view: select 2 groups → Export → CSV columns
    `severity,count,signature,sample_message,file,line,first_seen,last_seen` match the screen.
14. Toggle Live, append lines from a shell → rows prepend within the interval; scroll down mid-tail
    → "N new" pill increments; click pill → scrolls to top and clears.
15. Live on + a signature written repeatedly → mute it → list refetches without it and later ticks
    stop delivering it.
16. Live on → rotate the log out (`mv debug.log debug.log.bak; echo err >> debug.log`) → list
    replaces with the new file, no stale rows, no duplicate flood, cursor recovers.
17. Live on → toggle a severity filter → list refetches to the new shape; later ticks only deliver
    matching entries; a raced tick does not inject mismatched rows.
18. **Live on an empty log**: Clear log, toggle Live, then write a new error → it appears within one
    interval. *(Expected to FAIL on the current build — §1.1; re-test after the fix.)*
19. Stats: cycle 24h/7d/30d and hour/day → chart, KPIs, breakdown refetch; a log with
    unknown-severity lines buckets them under "Unknown" without crashing; click a Top-signature row
    → lands on Logs with severity + escaped-prefix regex pre-filled and matching rows (works for an
    "Unknown" row too).
20. Settings → Custom log path: enter the path to **wp-config.php** → Test path REJECTS it and Save
    does not persist; enter a not-yet-existing `*.log` path → "allowed, created on first write";
    enter a path outside ABSPATH/WP_CONTENT → rejected with allowed roots listed.
21. Retention round-trip: toggle rotation on, set 10 MB / 3 archives, Save → hard-reload → values
    persist and render; enter 0 or 2000 → inline error, Save disabled; toggle off + Save + reload →
    off, previous numbers retained underneath.
22. Monitoring: enable master toggle with no channel → Save blocked ("enable at least one
    channel"); email `foo@` and webhook `ftp://x` → inline errors; set a valid email → Send test
    alert → per-channel outcome list + toast, and the email actually arrives / webhook endpoint
    logs a hit.
23. Keyboard-only pass: from the **Settings** tab press `g` / `t` / `/` → app switches to Logs and
    performs the action; `?` opens the shortcuts modal, Esc closes; tab strip Arrow-Left/Right
    wraps, Home/End jump; row ⋮ menu opens with focus on the first item, ArrowUp/Down wraps, Esc
    closes; complete a full filter→select→mute flow without the mouse.
24. Screen-reader spot check (NVDA / VoiceOver): rows announce severity + message; the header
    entry-count updates politely while tailing; tabs announce selected state; icon-only buttons
    (🔕 mute, preset ×, row ⋮, ⤓ download) have accessible names — the emoji is not read.
25. Admin surfaces: admin-bar badge shows today's error count and links into Logscope, and
    disappears when disabled in Display settings; Dashboard widget lists recent errors; Site Health
    → Status shows the Logscope test with a sensible verdict for healthy and fatal-laden logs.
26. Multisite smoke: network-activate on a fresh multisite → no activation fatals, Logscope loads
    on a subsite, cap present for admins; deactivate cleanly.
27. Uninstall: Deactivate → Delete via the Plugins UI →
    `SELECT option_name FROM wp_options WHERE option_name LIKE '%logscope%'` returns **zero rows**
    (options + `_transient_logscope_*`); `logscope_filter_presets` usermeta gone for all users;
    `logscope_scan_fatals` / `logscope_rotate_logs` cron rows gone; `logscope_manage` cap removed
    from every role.
